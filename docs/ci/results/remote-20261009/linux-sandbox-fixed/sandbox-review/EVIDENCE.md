# Linux Chrome sandbox setup review

The historical Ubuntu native tests exit with Chrome SIGABRT, but retained job logs lack Chrome stderr. That signal alone does not identify AppArmor or a missing SUID helper. The new bounded preflight preserves the raw native Chrome stdout/stderr before deciding whether configuration is warranted.

Chrome 155 source still supports CHROME_DEVEL_SANDBOX. The official AppArmor user-namespace restriction guide recommends this helper as a way to work without disabling Ubuntu security features. The helper is installed only after the browser explicitly reports No usable sandbox or its exact misconfigured SUID-helper error, and only on a non-root GitHub Actions Linux runner. The action-selected matching helper is copied to a dedicated root-owned 4755 file, checked against the source digest, and a separate sandboxed renderer probe must succeed before native tests inherit its path. Unknown failures remain fatal. Global host policy and browser engine bytes are unchanged.

The local cloud raw Chrome 155 probe exited SIGABRT with No usable sandbox. The script then refused privileged installation because this cloud environment is not the designated GitHub runner. This confirms diagnostic capture and containment, not the cause or resolution on the remote Ubuntu runner. The cloud wrapper was rejected because it is not an ELF executable. No sandbox helper was installed locally. All raw logs and report.json values are retained.

frozen-source contains the exact two CI files at review freeze. validation.json records scoped Python syntax, actionlint and whitespace checks. sources.json identifies authoritative versioned source URLs; the two 404 paths are observations, not references used as evidence. Historical local-preflight profiles are excluded from this manifest; only final logs, reports, source and validation metadata are frozen. No Cargo, global format or Clippy checks were run while concurrent Firefox implementation was in progress.
