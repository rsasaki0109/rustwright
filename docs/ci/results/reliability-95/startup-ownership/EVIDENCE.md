# Startup process ownership correction

Six identical regression bodies fail before the correction and pass afterward: Chrome and Firefox startup timeouts, external launch-task cancellation on both backends, persistent Chrome timeout, and Chrome early exit. The initial unit suite records four existing passes and six failures; the corrected suite passes all ten. One additional successful Chrome readiness/ownership-transfer control then raises the final passing suite to eleven. Exact before/after source, original logs, actual process IDs, directory observations and returned BrowserError log paths are retained. The shared helper and original regression bodies were byte-compared across stages.

The fixtures are executable shell scripts that record their own PID/launch arguments and exec sleep as that same process, never exposing a browser endpoint. The early-exit variant returns17. A Unix kill -0 observation distinguishes a killed-and-reaped child from a running/zombie process. On expected baseline failures the fixture independently sends KILL and removes its owned test profile, preventing live synthetic processes from remaining. Successful readiness is injected only for the separate launcher ownership-transfer control; no compatibility assertion or browser engine is bypassed.

The startup guard owns the child immediately after spawn and Chrome's ephemeral profile before later fallible work or readiness waits. Drop kills and reaps the child before removing its owned profile; readiness transfers ownership into the returned process owner. Caller Firefox and persistent Chrome profile sentinels remain. Ephemeral Chrome stderr is captured outside its profile so failure logs survive profile cleanup; those actual returned paths contain the fixture marker. A successful returned ephemeral owner removes its external log on Drop, preserving previous successful-launch cleanup behavior. Failure/cancellation logs remain available to the caller; stderr capture options and persistent-profile logging are unchanged.

Package-scoped stable Clippy, Rust1.85 all-target compilation, formatting and whitespace checks pass. No real browser launches or heavy probes ran during the root memory measurement; these controlled tests ran only after its quiet window ended. The synthetic tests are Unix-only; shared production ownership code uses standard Child APIs on all platforms. Remote CI/native success on the final combined source must be recorded separately.

The guarantee covers directly owned Child processes, not descendant trees. OS kill/wait and filesystem operations have no independent hard deadline; kernel refusal or cleanup errors remain limits. Failed kill/reap is logged and an ephemeral profile is retained when process exit cannot be confirmed. This is a correction of an identified startup ownership leak, not a general leak-freedom, native sandbox or SOTA claim.
